# 从情感词典到 RLHF：一个文科生的数据标注项目复盘

> 作者：柳清桦（汉语言文学 · 2027 届）
> 项目地址：github.com/han-nlp/sentiment-lexicon

## 一、起点：一本"会吵架"的词典

最开始我只是想解决一个很小的问题：小红书评论里的"绝绝子"，到底是夸还是骂？

我用 Python 写了个情感词典，把网络新词按正面/负面/中性归类，做自动标注。第一版跑出来，准确率只有 **65.3%**。错得很典型：

- "被暖得破防了"被判成负面——"破防"在我词典里是负面，但这里是感动；
- "排队两小时就这？绝绝子"被判成正面——"绝绝子"被我写成了正面，但这里是反讽；
- "不是不喜欢"这类多重否定，极性直接翻转。

那一刻我意识到：**词典解决的是"词"，但情感活在"语境"里。** 而判断语境，恰恰是语言学训练的主场。

## 二、方法：把"语感"变成"规则"

语言学训练给我的不是某个软件，而是一套思考方式：语义学让我区分词的概念义和语境义，语用学让我关注"言外之意"，修辞学让我识别反讽和双关。我把这些"只能意会"的语感，拆成标注员可以执行的规则：

1. **三维标注体系**：情感极性（正/负/中）、强度等级（1–5）、歧义标记（反讽/双关/多义/无）。主观判断第一次有了结构化的落点。
2. **四步 CoT 推导**：词性用法识别 → 语境情感分析 → 歧义/反讽处理 → 判定+置信度。置信度低于 60% 的样本不硬判，转人工。
3. **错误归因闭环**：发现问题 → 归因分类 → 优化规则 → 重新验证。

我把 V1 的 17 条典型错误归成四类（词典遗漏、歧义词、长句误判、反讽），逐条改规则。第一轮迭代后 **82.1%**，第二轮引入强度等级和分句聚合策略后，达到 **94.0%**。

数字本身不大，但这套"用数据定位问题、用规则解决问题、再用数据验证"的闭环，让我真正理解了工业界标注团队是怎么工作的。

## 三、延伸：从 SFT 到 RLHF

情感分类本质是 SFT（监督微调）阶段的标注。我开始好奇 RLHF 阶段人类偏好是怎么被"写"进数据的，于是自己设计了一套偏好排序规范：

- **四个评分维度**：准确性（30%）、帮助性（30%）、安全性（25%）、表达质量（15%）；
- 一条**安全覆盖规则**：安全性只有 1–2 分时，再"有用"的回答也一票否决；
- 完成 15 对偏好标注，每对都必须写清"决定性差异是什么"，而不是含糊地说"B 更好"。

做到这里我有个很深的体会：**偏好标注标注的不是"对错"，而是"取舍"。** 比如"用高中生能懂的话解释机器学习"，一个学术化但正确的回答，会输给一个用"教小孩认猫"打比方的回答——因为它违背了用户的真实指令。这种判断，靠的不是代码，而是对"人到底想要什么"的理解。

我还设计了 5 类红队测试场景（渐进套取、歧义陷阱、角色扮演越狱、偏见引导、信任后攻击），专门测试模型的安全边界会不会在多轮对话里被一点点撬开。

## 四、文科生做标注，优势到底在哪

常有人问：数据标注不是理工科的事吗？我的体会恰恰相反。

大模型发展到今天，"听得懂字面"已经不是难事，难的是**听得懂言外之意**——反讽、双关、省略、文化梗、混合情感。这些正是中文语言学训练的核心内容。我能快速判断"这优化可真好啊，3090 跑 PPT"是反讽，不是因为我会写算法，而是因为我理解"期望违背"这个语用信号。

当然，文科生也要补工具课。我自学了 Python（pandas）做数据清洗、用 SQL 做多表一致性校验、用 IAA（标注者间一致性）指标做质量评估。**语言学负责"判断得准"，工具负责"跑得动、可复现"，两者合起来才是一个合格的 AI 训练师。**

## 五、这份项目教会我的事

- 标注规则不是写出来的，是在一个个错误案例里**反复打磨出来的活体规范**；
- 质量不是"检"出来的，是靠明确的维度、可执行的 SOP 和数据闭环**保**出来的；
- 94% 不是终点——它只代表"规则在这 150 条验证集上有效"，真实语料永远有新的反讽和梗，迭代不会停止。

如果你也在做中文 NLP 数据，欢迎一起交流标注规范设计和质量迭代的方法。
